Verovo 是我做的一个核对 AI 任务费用与交付的工具；这篇用它的内置合成样例。

**关键结论**

- Agent 账单不只有 token：搜索、浏览器、OCR、翻译、存储都可能按次、按页、按分钟单独计费。
- “费用通过”不等于“交付合格”；“缺记录”也不等于“失败”，它只能标“无法证明”。
- 验收要分两张表：费用表看金额、单价、用量；交付表看任务数、人工介入、完成证据。
- 本文使用 Verovo 0.13.0 的内置合成样例，不是客户数据；命令、输出和版本都在复现附录。

## 一、问题：账单对了，活就干完了吗

AI 任务的验收，经常被压缩成一个问题：账单对不对？

账单当然要对。但账单只覆盖“钱有没有按规则算”，不覆盖“活有没有按规则干完”。

一个任务可以同时出现：

- 费用通过；
- 交付不通过；
- 某一项无法证明。

如果只看总览颜色，很容易把“费用通过”当成“任务完成”。这篇要做的，就是把三个状态分开。

## 二、为什么 Agent 账单不止 token

先想象一个竞品调研任务。下面的调用量和 55 美元费用是讲解用的虚构例子，不是供应商报价，也不是 Verovo 内置样例。

它要搜 20 个竞品官网，打开 50 个商品页，把图片里的价格 OCR 出来，翻译几段英文，最后生成报告。

月底账单可能是这样：

| 项目 | 费用 | 计价单位 |
|---|---:|---|
| 模型 token | 20 美元 | 按 token |
| 搜索 API | 15 美元 | 按查询次数 |
| 浏览器/抓取 | 10 美元 | 按运行分钟 |
| OCR | 5 美元 | 按页 |
| 翻译 | 3 美元 | 按字符 |
| 存储/导出 | 2 美元 | 按 GB |

合计 55 美元。模型 token 只是其中一项。

这带来三个容易被忽略的问题：

1. **计价单位不同**：模型看 token，搜索看次数，浏览器看分钟，OCR 看页数。你按“任务”估算，供应商按“调用”计费。
2. **重试可能计费**：页面打不开重试三次，搜索没结果换关键词再搜；是否收费取决于服务、失败阶段和计价规则，需要对照调用日志核实。
3. **重复调用**：同一个页面抓两遍、同一段话翻译两次；没有去重和缓存，账单就会虚高。

这些差异需要同时检查调用日志和计费规则。派活时先写清“允许调用什么、最多调多少次、超了怎么办”。

## 三、合成样例：三个状态怎么分开

为了把问题缩小，Verovo 的内置合成样例只保留三项：

- 约定金额 100 美元，本地记录也是 100 美元；费用这一项，通过。
- 交付规则写着“需要人工救场的任务最多 2 个”，记录里是 5 个；交付这一项，不通过。
- 还有一项外部完成记录没有提供；报告不猜，标“无法证明”。

三个结果同时成立。

这不是“账单造假”，也不是“AI 一定偷懒”。它说明：**费用表和交付表，是两张表。**

| 表 | 看什么 | 本例结果 |
|---|---|---|
| 费用表 | 金额、单价、用量、规则 | 通过 |
| 交付表 | 任务数、人工介入、完成证据 | 不通过 |
| 证据表 | 完成记录、来源、哈希 | 无法证明 |

“无法证明”不是“失败”。

缺记录，可能是供应商没回传，可能是文件没保存，可能是权限没开，也可能是任务真的没做。因此要区分三种判定：

- 失败：按约定修复、补交或重新验收；
- 无法证明：只能补证据，不能直接判死；
- 通过：要有规则、有记录、有回执。

把“失败”和“不知道”分开，是验收里最容易被省掉、也最值钱的一步。

## 四、怎么换成自己的任务

不用一上来买工具。先做三件事：

**先写任务合同。** 允许调用哪些工具；每类工具最多多少次；总预算上限；重试几次；人工救场最多几次；什么算完成；证据放在哪里。

**再给每次调用留 ID。** 任务 ID、工具名、调用时间、输入摘要、输出摘要、费用。账单来了，按任务 ID 对，不按供应商名字猜。

**最后做三态表。** 通过、失败、无法证明。不要用“应该没问题”填表；缺证据就写缺证据。

一个可用的顺序：

1. 先写费用规则，跑一次，确认金额和单价口径；
2. 再写交付规则，跑一次，确认任务数和人工介入；
3. 最后补完成记录，缺什么标什么，不猜。

## 五、边界：工具不能替你签字

这次运行验证的是“给定规则与给定记录是否匹配”。

它不验证：

- 规则本身是否合理；
- 记录是否真实；
- 合同是否适用；
- 是否应该付款、接受交付或要求补救。

哈希有助于追踪所用文件，不会证明记录本身真实。缺证据不会自动变成失败或成功；它只是“无法证明”。

真实业务里，是否付款、是否验收、是否追责，仍要业务负责人结合具体约定判断。

## 六、复现附录

### 环境

- 日期：2026-11-05；本轮重新运行，退出码 0。
- 项目：Verovo 本地源码，版本 0.13.0；本次 HEAD `4c6ac4bfa2887d63643bced1dc3a70fd699dfd82`。
- 运行环境：Python 3.9+；本次未执行新的 PyPI 安装，也未在豆包、WorkBuddy 等宿主内运行。
- 输入：项目自带合成数据，不是客户数据。

### 命令

```bash
python3 healthcheck/verovo review --sample \
  --html buyer-review.html \
  --json buyer-review.json
```

### 输出

```text
CHARGES: PASS (1 checks; 0 evidence gaps)
DELIVERY: FAIL (2 checks; 1 evidence gaps)
[UNPROVABLE] delivery / completion-evidence
```

### 失败与恢复

- **命令找不到**：确认在仓库根目录，且 `healthcheck/verovo` 存在。
- **Python 版本不够**：README 要求 3.9+。
- **输入格式不对**：先跑 `--sample`，再按示例结构改自己的 JSON。
- **报告打不开**：HTML 是本地文件，用浏览器直接打开。
- **结果和预期不一致**：先看 JSON 里的逐项判定和哈希，再看规则/记录。
