你准备做一台家庭机器人，拿到一份 20 万条讨论的数据。最诱人的做法是按提及量排需求：清洁最多，就做清洁；人形很热，就做人形。但这个顺序跳过了两个问题：是谁在说，话里有没有实际使用经历？

对产品经理来说，数据的价值是帮助决定下一步找谁、测什么、暂缓什么。这篇沿着这三个决策，解释怎样把公开讨论变成可验证的产品判断。

## 一、先分清你数的是什么

这批研究保留了 2023 年 1 月至 2026 年 8 月的 208,755 条公开讨论记录。一个人可以发多条，一个帖子也可以收到多个回复，所以记录数不是用户数。

其中，带扫地机标签的记录有 44,288 条，人形为 2,595 条。形态是多标签字段，同一条可以同时提到两者；大量记录只谈场景或行业，没有具体形态。不能把 20 万条都说成家庭机器人的使用评价。

这一步会改变后面的工作：想研究污水箱维护，就去找已有产品的使用经验；想研究人形在家庭里是否省事，就需要连续试用记录。一个总数再大，也不能替代对这两种材料的区分。

## 二、两类记录不能拼成购买漏斗

| 本样本的规则标签 | 扫地机 | 人形 |
|---|---:|---:|
| 价格或购买意向线索 | 2,134 | 358 |
| 自述购买、拥有或使用线索 | 1,289 | 4 |

这里最容易做错的是用第二行除以第一行，写出 60.4% 和 1.1% 的“转化率”。两行不是同一批人的前后轨迹，没有建立用户匹配、购买时间和观察窗口，结果不能这样解释。

而且“我买了”只说明作者自述购买；它不自动证明用了半年、再次购买或愿意推荐。原始规则会用购买、持有和使用等关键词筛候选记录，尚未逐条人工核实。

这些数量仍然有用。1,289 条是寻找扫地机真实使用者的线索池，可以优先核实维护、退换和复用；4 条人形线索提醒研究者，当前采样里家庭使用证据薄弱，下一步应该补试用观察。它们决定研究投入的方向，不证明购买转化或行业成熟度。

## 三、标签要翻译成问题，不能翻译成能力

以两种常见误读为例。

**关键词命中不等于用户痛点。** 原筛查把 clean、wash、hair 等放进清洁维护词组；clean 可能只是在说“打扫得干净”，不是“清理机器很麻烦”。因此原来的 32.1% 不能写成“32.1% 用户抱怨维护”。要判断维护是否影响复用，需区分提及、抱怨、实际行为和影响，再抽样复核。

**场景共现不等于产品能力。** 扫地机拥有/使用线索中，535 条同时标了家务清洁，44 条标了老人照护，37 条标了取送/归位。一个用户说“给父母买了扫地机，仍需要有人帮忙取物”，就可能同时出现多种场景。它不证明扫地机能照护或取物。

这两类问题对应不同动作：关键词先帮助找原文，原文再拆出谁遇到什么困难、现在怎样解决、付出什么代价。只有任务、行为和对象明确，才进入产品讨论。

因此，不应给每个标签都配一个功能建议。比如“给父母买”更可能引出购买者、使用者与维护者的责任分工；“失败恢复”则要看中断后谁来救场。这比简单增加一个老人模式或智能按钮更接近问题。

## 四、人形产品要比较组合任务

扫地机与人形不是同一品类。把两者放在一起，是为了比较家庭劳动怎样被转移，而非谁的讨论量更大。

扫地机主要替代地面清洁。人形的额外价值应体现在一个有限场景内连续完成多种任务，例如客厅整理中的识别、分类、拾取、归位。分别演示四个动作，不能证明四个动作可以连起来完成。

比较时，把用户时间分成四段：准备、设备运行中的看护、故障接管、收尾维护。再记录任务切换时需要人做什么。如果每换一个任务都要重新摆物、下指令、换工具，多个技能未必变成更省事的产品。

现有评论缺少同一家庭连续任务的观察，不能用场景标签代替这项测试。这也是为什么“没有找到使用线索”不等于“现实中没有能力”。

## 五、把研究带到下一次试用

选一个明确的人群和场景，比如双职工家庭晚间整理客厅，把目前使用的人力和设备写成基线。机器人跑同一组任务，保留全程记录，记录完成情况、接管位置、恢复时间和收尾劳动。

若只是某个动作更快，却增加了整套流程的准备工作，优先改流程；若任务切换总要人干预，优先改切换与恢复；若完成得稳定但用户不愿再用，则回访频率、噪声、空间和维护代价。

公开讨论帮助你挑问题，连续使用帮助你判断产品。下次拿到一份大样本报告，可以先找其中一条最影响决策的结论：它对应的是一句表达、一次行为，还是同一用户的一段经历？

## 六、复现附录

### 输入与字段

- 严格样本：`strict_master_2023plus.jsonl.gz`，208,755 条。
- 关键字段：`product_form`（列表）、`demand_evidence_level`（E0—E5）、`corpus_role`、`scene_labels`。
- 数据窗口：2023-01-01 至 2026-08-16。
- 本次复核日期：2026-11-05；未重新采集，未改动源文件。

### 编码映射

| 正文说法 | 编码 |
|---|---|
| 场景上下文 | E0 |
| 任务/痛点 | E1 |
| 替代方案 | E2 |
| 接受方案 | E3 |
| 购买意向/价格讨论 | E4+ |
| 拒绝或负面购买线索 | E4- |
| 自述购买、拥有或使用线索 | E5 |

### 复核脚本

```python
import gzip, json
from collections import Counter

forms, ownership_candidates = Counter(), Counter()
total = 0

with gzip.open("strict_master_2023plus.jsonl.gz", "rt", encoding="utf-8") as f:
    for line in f:
        if not line.strip():
            continue
        row = json.loads(line)
        total += 1
        forms_in_row = row.get("product_form", [])
        if isinstance(forms_in_row, str):
            forms_in_row = [forms_in_row]
        for form in set(forms_in_row):
            forms[form] += 1
            if row["demand_evidence_level"] == "E5":
                ownership_candidates[form] += 1

print("records", total)
for form, count in forms.items():
    print(form, count, round(count / total * 100, 2), ownership_candidates[form])
```

旧报告与本次重数的差异：扫地机 44,150 → 44,288，人形 2,534 → 2,595，机器狗 1,097 → 1,133，陪伴 2,791 → 2,806；扫地机拥有/使用线索 1,285 → 1,289。差异来自数据版本和标签重算，不是新采集。
