    <h1>AI applications will not be stuffed by Agent, they will be removed first.</h1>
    <p class="post-subtitle">From the perspective of DSH and Codex Harness: the basic unit of software is changing from an App to a runtime combination.</p>
    <div class="post-meta">
      <time datetime="2026-08-21T10:00:00+08:00">2026-08-21</time>
      <span>10 minutes to read</span>
      
      <a class="post-translation" href="/notes/ai-apps-unbundled-before-agent-filled/" hreflang="zh-CN">阅读中文版 →</a>
      
        <span class="post-tags">
          <a href="/en/tags/#agent">#Agent</a><a href="/en/tags/#harness">#Harness</a><a href="/en/tags/#capability%20economy">#Capability Economy</a><a href="/en/tags/#saas">#SaaS</a><a href="/en/tags/#ephemeral%20software">#Ephemeral Software</a>
        </span>
      
    </div>
  </header>

  <div class="prose">
    <p>In the past year, the most common product idea of AI application is to add an Agent to existing software: CRM plus sales agent, document tool plus writing agent, design software plus creation agent.</p>

<p>If you put DeepSeek Harness (DSH) and Codex Harness together, you will see another more radical route: the future software may not be a well-encapsulated App. Models, skills, tools, data, execution environments and interfaces can be temporarily combined at runtime and disappear after the task is completed. Today we open apps one by one; in the future, Agent may temporarily assemble an &quot;application&quot; according to the task. This route changes the basic unit of software.</p>

<h2 id="harness-正在变成新的软件运行时">Harness is becoming a new software runtime.</h2>

<p>DeepSeek&#x27;s definition of Agent is very straightforward:</p>

<blockquote>
  <p>Agent = Model + Harness</p>
</blockquote>

<p>DSH makes models, tools, skills, sessions, sandboxes, storage, Loop, scheduling and UI into plug-ins. Behind the standard mode, PTC mode, minimalist mode and creation mode are different runtime combinations. The creation mode can even check the current runtime, test the plug-ins in memory, and then combine them into new presets.<a href="https://deepseek.com/harness/">DeepSeek Official Preview Page</a></p>

<p>Codex takes a different path, but the landing point is very close. Codex&#x27;s Web, CLI, IDE extensions and desktop apps share the same set of Harness; App Server exposes Agent Loop, session, configuration, authorization and event flow to different clients through two-way JSON-RPC. External products can also use this to embed Codex without re-emalizing the whole set of Agent logic.<a href="https://openai.com/index/unlocking-the-codex-harness/">OpenAI：Unlocking the Codex harness</a></p>

<p>Both companies are doing the same thing: changing Harness from the implementation details inside the product to a reusable and combinable runtime. DSH is still in the developer preview stage. The official clearly reminds that the core plug-ins and APIs will also change, and Codex App Server is also evolving rapidly; they are not yet stereotyped industry standards, but the direction is clear enough.</p>

<h2 id="app-会变成一次运行时组合">The app will become a runtime combination.</h2>

<p>Traditional software packages interfaces, processes, business logic, data and execution capabilities together. Users enter the App and use these capabilities layer by layer. Harness-native software is more like:</p>

<div class="language-text highlighter-rouge"><div class="highlight"><pre class="highlight"><code>用户目标
   ↓
Agent
   ↓
Harness
   ↓
按任务选择 Model / Skill / Tool / Data / UI
   ↓
执行并交付结果
</code></pre></div></div>

<p>For example, the user proposed to &quot;study the changes of Xinjiang&#x27;s overseas market in the past two years and give me a report with charts&quot;. Harness can temporarily load search, financial data, PDF reading, spreadsheets and chart rendering to form a research application; after the report is delivered, this combination does not need to continue to exist. This kind of software can be called Ephemeral Software: it is generated for a task, runs once or several times, and then disappears.</p>

<p>The software will not become less because of this. When the cost of development and assembly decreases, a large number of internal tools, personal tools and disposable tools that were not worth developing separately in the past will appear; what reduces is the need for each software to become a long-term product.</p>

<h2 id="saas-会被拆包workflow-最先承压">SaaS will be unpacked, and Workflow will be the first to bear the pressure.</h2>

<p>Today&#x27;s SaaS usually sells five layers of things to users together:</p>

<table>
  <thead>
    <tr>
      <th>Tier</th>
      <th>Content provided by SaaS</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Interface</td>
      <td>GUI</td>
    </tr>
    <tr>
      <td>Workflow</td>
      <td>Fixed process</td>
    </tr>
    <tr>
      <td>Logic</td>
      <td>Business rules</td>
    </tr>
    <tr>
      <td>Data</td>
      <td>Business data</td>
    </tr>
    <tr>
      <td>Execution</td>
      <td>Perform the action</td>
    </tr>
  </tbody>
</table>

<p>The easiest thing for Agent to take over is Interface and Workflow, because natural language is becoming a new interactive entrance, and Harness can be responsible for process arrangement.</p>

<p>In the past, sales had to enter CRM, screen customers, check records, write emails, and set up follow-up. In the future, he just needs to say: &quot;Find out the 20 customers who have not been followed up in the past two weeks but have the highest probability of making a deal. Write an email separately, and let me confirm it with high-value customers first. A large number of CRM pages and click paths will return to the back of Agent, but customer records, permissions, historical interactions and audit logs will not disappear. The more Agent can perform tasks, the more real data and action interfaces are needed.</p>

<p>Therefore, SaaS will not &quot;die&quot; neatly, and the differentiation will be more obvious:</p>

<ul>
  <li>Workflow SaaS, which creates value by users manually operating fixed processes, is more risky.</li>
  <li>The value of the System of Record, which grasps the business facts, may rise.</li>
  <li>The System of Action, which can complete real actions, will also become more important.</li>
</ul>

<p>To judge whether a software company is safe, you can ask a very direct question: Does Agent have a reason to bypass it? If Agent only needs its API and not its interface, the pricing, distribution and moat of the product will have to be recalculated.</p>

<h2 id="软件市场会从-app-economy-转向-capability-economy">The software market will shift from App Economy to Capability Economy.</h2>

<p>Today, the basic units of the software industry are Application: Photoshop, Figma, Salesforce, Expedia. Harness sees each ability: remove_background(), render_video(), query_customer(), book_flight(). After the application is opened, what the Agent needs to do is to find, compare and call the ability in the task. The plug-in architecture of DSH has pushed this matter inside the runtime; its subagent interface also allows multiple providers to be registered in the same context, including Codex, Claude Code and DSH SDK.<a href="https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/subagent.md">DeepSeek Harness：Subagent</a></p>

<p>Agent also began to become another Agent&#x27;s Tool. The software ecology is no longer just a row of icons in the App Store, but will gradually grow into a Capability Graph: the general agent is responsible for understanding the goal, the professional agent takes over the sub-task, and then calls the underlying tools and services. New distribution problems have also emerged: developers used to study &quot;how to let people download my App&quot;, and in the future, they will have to study &quot;how to let Agent choose my ability&quot;. This will generate new infrastructure: Capability Registry, Agent Search, Reliability Ranking, Eval, Attribution, Payment and Reputation System.</p>

<h2 id="模型很重要但模型优势不等于应用壁垒">The model is very important, but the advantages of the model are not equal to the application barriers.</h2>

<p>When the model is decoupled from Harness, multiple models can be connected to the same set of runtime: classification is given to the small model, the code is given to the Coding Model, and complex reasoning is then called Frontier Model. The top model is still of great value, but the application does not have to bet all its capabilities on a single model. This will put pressure on a batch of &quot;LLM API + Prompt + Workflow + Beautiful UI&quot; applications: Agent Loop, tool call, context management, sandbox, permissions, Skill and Subagent are becoming public infrastructure. Simply putting these components together will make it more and more difficult to form long-term barriers.</p>

<h2 id="ai-应用的壁垒会集中到五种资产">The barriers to AI applications will be concentrated in five assets.</h2>

<p>Harness can copy the workflow, but it cannot generate assets in the real world out of thin air. What&#x27;s more worth seeing is five things: unique Context and Data (customer records, case materials, inventory, historical interactions), Execution (real actions such as payment and delivery), Feedback Loop (whether the task results can continue to improve judgment and execution), Permission and Trust (whether users dare to authorize high-risk operations), Distribution and Network (whether the supply and demand relationship is networked). The value of the legal agent will not come from a prompt who &quot;knows the law well&quot;, but will come from the case database, practice authority, lawyer network and case results; the moat of e-commerce agent and enterprise AI is the same, falling on data, authority, execution interface and history.</p>

<h2 id="代码会变便宜什么叫正确会变贵">The code will become cheaper, and &quot;what is right&quot; will become expensive.</h2>

<p>OpenAI&#x27;s Harness Engineering experiment provides a very specific signal: the code base of an internal beta project reached about one million lines after five months, covering application logic, infrastructure, tools and documents; during this period, about 1,500 PRs were created and merged, initially driven by three engineers to Codex.<a href="https://openai.com/index/harness-engineering/">OpenAI：Harness engineering</a></p>

<p>OpenAI&#x27;s summary of this experiment is not &quot;the programmer has disappeared&quot;: the team&#x27;s main work has shifted from writing code by hand to designing the environment, expressing intentions and establishing a closed loop of feedback. The faster the code is generated, the more the really scarce things move upstream - specification, architecture, test, eval, policy, context, observability, feedback loop. Cost decline does not mean that software engineering becomes simpler: engineers should write &quot;correct&quot; into the environment so that Agent can check, correct and run continuously. The name Harness Engineering accurately describes this change.</p>

<h2 id="gui-不会消失它会变成-control-plane">GUI will not disappear. It will become Control Plane.</h2>

<p>All software turns into chat boxes, which is neither realistic nor unnecessary. Video timeline, 3D space, CAD, map and design canvas are still high-bandwidth input tools; after Agent completes the task, people also need to check, compare and confirm the results. The bigger change in GUI is that the operation layer gradually gives side to the control layer: what the Agent is doing, what data is used, how much money is spent, why this decision is made, which actions need to be approved, and where the failure is. The workbench will not disappear, but the center of gravity will shift from Workspace to Control Plane.</p>

<h2 id="商业模式会从-seat-economy-转向-machine-economy">The business model will shift from Seat Economy to Machine Economy.</h2>

<p>SaaS is charged by seat because people are operating the software. After Agent becomes the main operator, an Agent may replace a large number of page operations, while producing a much higher number of API calls than people. The pricing method will gradually move to Usage, Transaction, Outcome, Compute, Data and Agent Action.</p>

<p>This does not necessarily reduce the revenue of SaaS: a person opens CRM 20 times a day, and an Agent may call the interface 20,000 times. Software consumption has not disappeared. Consumers have changed from people to machines, and pricing units have also changed.</p>

<h2 id="接下来值得关注的五个位置">The next five positions worth paying attention to</h2>

<p>In the next three to five years, the most likely positions are in five basic positions:</p>

<ul>
  <li>Agent Runtime / Harness Infrastructure: Let Agent run stably for a long time.</li>
  <li>Context Infrastructure: Let Agent get the correct and updateable long-term context.</li>
  <li>Capability Economy Infrastructure: Help Agent discover, purchase and call services.</li>
  <li>Trust / Eval / Observability: Judge whether Agent and Tool are reliable.</li>
  <li>Vertical System of Action: Control industry data, execution ability and feedback closed loop, and directly deliver results.</li>
</ul>

<p>The last category of market may be the largest: AI recruitment, legal affairs, finance, e-commerce operation, market research, software development, content production and customer service. In the end, the competition is the data, permissions, actions and results that Agent cannot avoid when completing tasks.</p>

<h2 id="软件的第一用户正在从人变成-agent">The first user of the software is changing from a person to an agent.</h2>

<p>In the past, people were users and software was a tool; now, people are still users, Agent is an assistant, and software continues to be a tool. Going one step further, people are only responsible for putting forward goals, and Agent will become a direct user of the software. This is exactly the signal released by DSH and Codex Harness: the strengthening of Coding Agent is only a superficial change, and the underlying change is that the infrastructure of &quot;Agent as the first user of software&quot; begins to mature. Harness will platform Agent, Agent will absorb a large amount of Workflow, and the traditional App will then be disassembled into Experience, Context, Capability and Execution. The most valuable software company in the future may not have the most complete interface App; it may only have one ability, but that ability can master real data and perform key actions, and Agent cannot be bypassed.</p>
