Agent and software system

This topic is being questioned.

How can an Agent change from a one-time answer to a system that can be delivered continuously?

Cover: How the software takes over the long-term tasks assigned to the Agent - what context is needed, how the ability is called, how the execution facts are saved, and how to distinguish between use and value.

How to read: Read Agent Runtime first to see how an Agent holds the task state; then enter capability distribution and capability economy; and finally separate "used" and "creating value" by measurement methods.

Test: AgentMeasure and iRead provide checkable implementations and boundaries.
