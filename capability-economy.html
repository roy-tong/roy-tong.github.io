CURRENT CAMPAIGN · 当前战役

Agent Capability Economy

长期品牌是「AI 如何变成产品、系统与商业」，而当前最重要的结构性变化是：软件消费者正在从人变成 Agent。由此产生一个新问题——软件如何被发现、选择、调用、计量与付费。这是未来 6–12 个月唯一火力全开的专题。

THE THESIS

为什么是现在，为什么是这个问题

当 Agent 成为软件的消费者，软件经济的基础单位会从 App 变成 Capability：一个软件不再只被「人」安装、打开、浏览，还会被「Agent」发现、选择、调用、计量与付费。

这个转变已经发生，但行业讨论仍是碎片化的：有人讲协议（MCP）、有人讲工具（Skills）、有人讲支付、有人讲 marketplace、有人讲 observability。缺少一个完整问题把这一切串起来——Agent 作为新的软件消费者，整个软件经济如何重构。

在这个完整问题里，measurement 是必须先解决的空缺：没有可靠计量，就无法比较、定价与结算。AgentMeasure 不是先有产品再找论点，而是对这个判断的产品化验证。

  • 已有碎片Skills · MCP · API · CLI · Agent Runtime · Agent Marketplace · 自动交易 · Agent 使用软件
  • 缺少的一个完整问题：Agent 作为新的软件消费者，软件经济如何重构
  • 先决条件Measurement 先于 Payment：没有可靠计量，就无法比较、定价、结算
  • 品类窗口尚未形成稳定话语体系，存在定义窗口；这正是建立权威与引用的机会

TERMINOLOGY

计量语言

术语是被引用的最小单位。AgentMeasure 正在建立一套开放计量语言，先定义清楚每一个词。

  • Agent代表用户目标，自主获得上下文、选择能力并调用软件完成任务的软件消费者。
  • Capability软件可被 Agent 调用的一次能力，而非整个 App。基本单位从 App 变成 Capability。
  • Reach一次能力机会是否被 Agent 发现（发现层）。
  • Choice面对多个候选能力，Agent 如何选择（选择层）。
  • Use一次能力被实际调用与执行（调用层）。
  • Utility这次调用对任务产生了多少效用（效用层）。
  • Value效用如何转化为可结算的价值（价值层）。
  • Metering对能力使用的可靠计量，是 pricing 与 settlement 的前提。
  • Marketplace能力被发现、比较与交易的场所。
  • CaaSCapability as a Service：按能力而非按席位/安装计费的软件形态。
